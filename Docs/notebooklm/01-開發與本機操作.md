# 開發與本機操作

## 環境

需要 .NET 10 SDK、Node.js 24、npm 11 及可運作的 Docker。新資料庫與既有 CBCT 容器分開，使用本機 `25432` 連接埠；不使用既有 CBCT 資料庫。

## 啟動

在專案根目錄先啟動 PostgreSQL：

```powershell
npm run platform:db
```

使用兩個終端分別啟動後端與前端：

```powershell
npm run platform:api
```

```powershell
npm run platform
```

工作入口為 `http://127.0.0.1:5189/platform.html`，API 為 `http://127.0.0.1:5188`。前端開發伺服器將 API 轉送至後端。資料保存在 Compose volume `clinical-form-platform_platform-postgres`；關閉瀏覽器不會清除伺服器紀錄。

首次使用須在 `template/crf/` 安裝依賴：`npm --prefix template/crf ci`。後端 `dotnet run` 會還原所需套件；Development 啟動會套用 EF migrations。

## 合成資料開發身分

開發模式可切換開發管理員、表單設計者、獨立核准／審閱者、甲院及乙院研究人員。這些是明確開啟的 Development 專用身分，不能作為正式登入方式；非 Development 不註冊此機制。

除開發管理員可建立研究外，帳號需經該研究授權才能工作。建立研究的管理員取得該研究明確指派；不因此取得其他研究內容權限。

## 研究總覽工作台

總覽上方以資料列顯示可見受試者、院所、待填、待審閱及已鎖定數。主區是訪視工作清單，可搜尋研究代碼、訪視或表單名稱，也可依狀態篩選；按每列「開啟」會進入對應受試者與訪視，不必再次尋找。

右側顯示研究政策與設計、同意依據、收集及匯出入口。待填數只包含已建立訪視的應收表單。窄螢幕可在資料表內左右捲動，右側「開啟」保持可見；頁首提供「跳至主要內容」鍵盤連結。

工作區與表單採灰階／冷藍緊湊樣式，狀態仍以文字呈現，不只靠顏色區分。既有資料收集與核准規則不變。

## 操作順序

1. 管理員建立研究、院所，指派設計者、核准者與院端人員。
2. 在「表單設計」建立範本，從空白、JSON 或可編譯的 program.yaml 草稿開始調整。
3. 儲存、填理由並送審，切換另一位已授權核准者正式發布，再明確採用版本，設定適用訪視及每次訪視最多填寫次數（1–100）。
4. 在「研究與授權」建立受試者研究代碼；在「ICF 與收集依據」設計 ICF 草稿、填外部核准依據、送審，由設計參與人以外的授權人核准。再登錄院端簽署文件參考或核准免同意依據，由有確認權的人員確認。未核准 ICF 不能用於收集，正式內容不可覆寫；改版須另建文件，停用會影響後續收集關卡。
5. 建立訪視與表單次別，依固定版本填寫、儲存、送出、審閱及鎖定。
6. 更正已送出紀錄須理由並重新審閱；鎖定須先授權解鎖。可在資料疑問區建立、回覆及結案疑問。
7. 無填答的表單可填理由標記「未執行」；恢復須另填理由，重新檢查收集依據。兩次操作均保留稽核。
8. 在「資料查核與匯出」查看已建立訪視的收集進度，或填用途與理由建立 JSON 快照；目前最多 1000 筆，下載時再次檢查權限與依據。
9. 另建版本時使用主版.次版.修訂版格式，例如 2.0.0；新契約識別碼與版本同步。已儲存版本可比較欄位限制、條件、計算及版面差異；不包含尚未儲存編輯。

目前介面與 API 持續開發中；表單跨研究採用、附件、CTMS、匯出與正式登入等能力的完成證據見 [開發狀態](../planning/development-status.md)，不依按鈕或規劃推定已完成。

## 本機單一登入驗證

這是另一種開發啟動方式，使用隔離的 Keycloak；停止原 API 後執行：

```powershell
npm run platform:build
docker compose -f compose.platform-identity.yml up -d
dotnet run --project backend/FormPlatform.Api --launch-profile oidc
```

開啟 `https://localhost:7198/platform.html`，透過本機 IdP 登入。合成帳號設定位於 `infra/platform-identity/realm.json`，僅供開發；不要把該設定作為正式身分服務。開發 HTTPS 憑證需在自己的測試環境處理信任；瀏覽器自動驗收略過憑證檢查僅限本機測試設定。

已驗證登入、CSRF 寫入及登出；正式供應商、近期 MFA、服務帳號與維運設定仍須另行驗收。

## 管理員帳號操作

平台管理員可在「平台帳號管理」明確註冊 issuer|subject 身分與整合來源，或填理由啟用／停用帳號。註冊不會自動建立 IdP 帳號或給研究權限，須另行指派；不能停用自己目前使用的管理員。可將研究選單切至「新增／選擇研究」建立其他研究。

## 驗證命令

```powershell
npm run platform:test
npm --prefix template/crf run check
npm run platform:build
```

後端測試使用實際 PostgreSQL，建立隨機測試資料庫並在結束後刪除；需先啟動 `platform:db`。不對既有正式或 CBCT 資料庫執行清除。

## 常見問題

- 找不到研究：確認開發身分是否有未過期的研究／院所指派。
- 無法開始收集：確認研究及院所啟用，且有已確認、用途適用且版本有效的同意或免同意依據。
- 發布被拒：確認必要對應、版本狀態，及核准人不是設計參與人。
- 更正衝突：重新載入最新修訂後，再檢查並提交；不要盲目重送舊資料。
- API 無法啟動：檢查 PostgreSQL、`25432` 埠，以及 Development 組態。正式模式須另設可信任的 OIDC 供應商及資料庫設定。
