# 多種建表來源使用同一個視覺化編輯器

使用者選擇文件／AI 產生草稿、範本建立及空白建表均進入同一套視覺化編輯器，並特別確認後續調整需要視覺化編輯能力。因此視覺化編輯是第一版核心，不能僅提供 AI 產生與預覽，也不能要求一般使用者靠直接修改 YAML／JSON 才能完成後續修訂。

先接通既有計畫書轉草稿與人工編輯流程，再擴充範本重用；不同建表入口共用表單定義及審閱流程，避免 AI 產物與人工建表形成不同格式或分離的修訂路徑。YAML／JSON 維持底層規格角色；AI 欄位建議與 CDISC 對應須保留來源及待確認狀態。可編輯的欄位、規則與 ICF 內容範圍，以及審核後修訂的發布政策，仍待細化。
