# 研究表單平台：訪談範圍基準

更新日期：2026-10-28。以下產品決策已逐項確認；本文件的模組切分與開發順序為待整體確認的規劃建議，不表示已完成軟體實作或上線驗收。

## 產品目的

高效率建立、審閱及發布可重用研究表單，提供正式資料收集能力，支援 CTMS 與其他系統使用、讀取及受控寫入；第一版由單一營運單位服務多個研究與合作院所。

## 建議模組邊界（待整體確認）

1. 表單設計與範本：草稿、視覺化編輯、文件／AI 來源、版本、差異、審核與發布。
2. 研究脈絡與授權：研究、院所、受試者研究代碼、訪視、指派及外部代碼對應。
3. 表單執行與填答：共用呈現、後端驗證、草稿、送出、更正、審閱、鎖定及稽核。
4. 標準與同意政策：CDISC 候選及確認、研究編碼政策、ICF 核准版本、適用依據及收集關卡。
5. 附件整合：附件關聯與存取、既有上傳能力銜接及檔案驗證狀態。
6. 對外整合：讀取與寫入 API、外部登入、嵌入、事件通知及可重現匯出。

模組代表責任邊界，不預設六個微服務。共用呈現不表示僅靠前端執行驗證；正式控制由後端一致執行。

## 建議開發順序（待整體確認）

| 階段 | 交付與驗收重點 |
| --- | --- |
| 0：契約與基礎 | 盤點現有兩套 Studio 與 renderer 的重用界線，定義表單／填答版本、研究脈絡、狀態及授權模型；用合成資料驗證契約。 |
| 1：獨立 eCRF 流程 | 平台登入、研究建檔、編輯與預覽、必要 CDISC 對應、正式發布核准、訪視填答、更正、審閱、鎖定與受控匯出。收集關卡先具備受控依據登錄及確認，不能因完整 ICF 模組尚未交付而略過。 |
| 2：重用與 ICF | 版本化範本採用／差異、ICF 內容及核准版本、院端或集中保管、同意狀態與用途限制、一般附件。 |
| 3：CTMS 使用 | 脈絡代碼對應、讀取 API／事件、外部登入及嵌入；與平台入口驗證一致的院所權限及資料行為。 |
| 4：受控資料交換與影像 | 外部寫入／更正、重複與衝突處理、既有 CBCT 上傳串接、驗證結果同步與保存協調。 |
| 5：試點及正式上線驗收 | 合成資料全流程、合作院所使用驗收、跨院拒絕存取、外部寫入繞過測試、備份還原、稽核與資料匯出追溯；通過必要治理及驗收後才收真實資料。 |

各階段均須有相應驗證，階段 5 是整合驗收而非首次測試。既有上傳平台的上線缺口須納入串接驗收。
